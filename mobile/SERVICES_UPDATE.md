# 사용자 앱 추가 화면 적용 안내

이 ZIP은 이전 분석 결과 업데이트를 적용한 mobile에 병합하는 변경분입니다.
기존 mobile 폴더를 삭제하거나 통째로 교체하지 말고 같은 경로의 파일만 추가/덮어쓰기 하세요.
추가 npm 의존성이나 API 키는 필요하지 않습니다.

## 구현
- 신규 상처 등록: 사진 선택/촬영, 날짜 수정, 사진 변경/삭제, 분석 대기 기록 생성.
- 경과 기록: 기존 상처명/최초일 표시, 통증·붓기·진물 선택, 메모, 검증 후 해당 상처에 저장.
- 이전·현재 비교: 같은 상처의 기록 두 개 선택, 사진 확대, 현재 기록의 증상/메모 표시.
- 피부 질환 백과: 10개 예시 항목, 카테고리, 질환명/영문명/설명/태그 검색, 빈 결과 및 상세 안내.
- 병원/약국: 탭, 예시 지도 마커와 목록 선택, 검색, 영업 중 필터, 실제 지도 검색 연결.
- 마이: 시연 프로필, 문의 초안 작성/내역, 프리미엄 안내, 로그아웃.

## 범위
인증 없이 사용합니다. 등록 사진·증상·메모·문의 초안은 앱 실행 중 메모리에만 저장되며 종료/로그아웃 시 초기화됩니다.
실제 AI 분석, 지도 SDK/현재 위치/기관 API, 문의 전송, 결제는 연결하지 않았습니다.
지도 및 기관명·거리·영업 상태·평점은 Figma 예시 데이터입니다. 예시 기관으로 길찾기하지 않고 실제 지도 검색으로 안내합니다.
백과 내용과 분류 배지는 화면 시연용이며 검토된 의료 데이터/API로 교체해야 합니다.
갈색 원과 밴드 이모지는 기기 글꼴을 사용합니다. 나머지 신규 주요 아이콘은 원본 SVG/PNG를 포함합니다.

## 적용 및 실행
현재 사용 중인 feat/mobile-analysis-records 브랜치에서 계속 작업할 수 있습니다.
덮어쓰기 전 직접 수정한 파일은 백업하고 차이를 확인하세요. 이전 작업을 커밋해두면 비교와 복구가 쉽습니다.
ZIP 안 mobile 내용을 기존 SkinCare-AI/mobile에 병합한 뒤:

```bash
cd mobile
node --test tests/*.test.mjs
npx expo start
```

## 나중에 GitHub 업로드
지금 바로 푸시할 필요는 없습니다. 준비되면 기존 저장소의 mobile 폴더에서:

```bash
git branch --show-current
git status
git diff -- .
git add .
git diff --cached --stat
git commit -m "feat(mobile): add wound forms, comparison and service screens"
git push -u origin feat/mobile-analysis-records
```

브랜치명이 다르면 push 명령의 브랜치명을 실제 이름으로 바꾸세요. git add .는 mobile 안의 변경 전체를 포함하므로 목록을 확인하세요.
GitHub에서 develop을 대상으로 PR을 열면 됩니다. 이번 전달에서는 커밋/푸시를 실행하지 않았습니다.
node_modules, .expo, dist, .env 등은 기존 .gitignore로 제외해야 합니다.

웹: 신규 등록→경과 저장→사진 비교, 날짜 선택/확대, 검색/빈 결과, 병원/약국 전환/마커/길찾기 안내, 문의 초안/로그아웃.
