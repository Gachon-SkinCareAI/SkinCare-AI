# 비회원 우선 앱 공개 배포 검증

## 배포 범위

- 모바일: 로그인 전 홈·사진 촬영/선택·분석 진입, 비회원 동의와 기록 접근,
  선택적 학습 이용 동의, 회원의 위치정보 동의 및 주변 기관 검색.
- 백엔드: 비회원 소유권·동의·삭제 API, DB 마이그레이션 V006/V007,
  보관/백업 복구 시 학습 동의 철회 처리.
- 기존 AI 가중치, 데이터셋, 로컬 문진 모델, 소셜 로그인 키는 유지.
- 사용자 앱과 관리자 웹을 분리. `/admin/`은 실제 관리자 인증/API에 연결된
  기존 운영 화면을 배포한다. `admin-web/src`의 React 디자인은 샘플 데이터
  미리보기이며 원본을 보존한다.

## 관리자 웹 구현 범위

관리자 로그인, 문의·답변, 기관 정보 등록/수정, 분석 및 AI 상태,
자료 검수 이력, 감사 이력, 관리자 비밀번호 변경 화면이 있다.
사용자와 비회원 토큰은 관리자 API를 사용할 수 없다.
새 React 디자인의 실제 API 연결과 운영 기능 전환은 별도 미완료 작업이다.

## 첫 공개 적용에서 발견한 문제

DB 백업 체크섬과 V001–V007 적용, 기존 계정·분석·답변 수 보존은 확인했다.
하지만 읽기 전용 Docker의 `logs/` 경로에 파일 로그를 쓰려다 백엔드가
시작하지 못했다. 공개 연결은 열지 않고 컨테이너를 정지했다.

기본 로깅은 Docker가 수집하는 콘솔로 변경했다. 명시적 `file-logs` 프로필은
기존 파일 로그 설정을 유지한다. 사용하지 않는 레거시 파일 저장소는 시작 시
폴더를 만들지 않고 실제 업로드 요청에서만 생성한다. 관련 회귀 검사를 추가했다.
버전 2 재검사에서 읽기 전용 컨테이너의 백엔드 상태, 비회원 정책 API와
관리자 로그인 화면이 통과했다.

## 적용 도구와 복구

- `deploy/public-demo/update_guest_demo.py`: 기존 DB/백업 볼륨 소유권 확인,
  이전 이미지와 파일 보존, DB 백업 검증, 마이그레이션 이력 확인,
  백엔드 및 AI 준비 검사 후 HTTPS 재시작.
- DB 변경이 시작된 뒤 실패하면 공개 서비스를 정지한다. DB를 과거 백업으로
  자동 덮어쓰지 않는다. 적용 전 백업과 오류 기록을 보관하고 원인을 검수한다.
- 이미 적용된 마이그레이션은 이름과 체크섬을 확인하며 재실행하지 않는다.
- `Build-Public-Android.ps1`은 기존 공개 서명키로 업데이트 APK를 만든다.
  API 주소가 바뀌면 Gradle의 JS 번들 입력도 바뀌도록 하여 이전 주소 재사용을 막는다.
- 실제 실행 결과는 작업 출력 폴더의 `guest-upgrade.json`,
  `public-endpoint-checks.json`, `public-device-installation.json`에서 확인한다.

## 후속 확인

공개 서버 적용과 외부 HTTPS 검사는 완료했다. 현재 주소는
`https://decent-significance-representation-evaluations.trycloudflare.com`이며,
관리자 화면은 `/admin/`이다. 사용자가 Google/Kakao/Naver 콜백 추가를 확인했다.
독립된 외부 GET 검사에서도 정책/관리자 정적 화면은 200,
인증 없는 관리자 데이터와 분석 기록 요청은 401을 확인했다.

초기 Android 버전 7 빌드 조사에서 CMake 버전 조회는 정상이었으며,
상세 Gradle 로그에서는 React Native 0.88.0 release AAR(171,558,810바이트)
다운로드가 진행 중임을 확인했다. 화면에 CMake 작업명이 오래 남아 있다는
사실만으로 CMake 실패를 확정하지 않는다.
느린 다운로드를 진행하던 Gradle 작업은 중지한 뒤 아래 버전 정렬을 진행했다.
PC 실행용 `outputs/guest-public-v1/Build-And-Install-App.cmd`를 준비했다.
이 파일은 빌드 도구 사전 검사, APK 생성, 기존 인증서/서버/권한 검사,
ADB 데이터 보존 설치를 순서대로 실행하고 단계별 상태를 저장한다.
첫 PC 사전 검사는 정상 종료한 CMake의 종료 코드를 읽지 못해 실패로 처리했다.
프로세스 핸들을 직접 유지하도록 수정했으며 Windows PowerShell의
`-NativeToolOnly` 실행에서 종료 코드 0과 `native-tool-verified`를 확인했다.
이후 Windows PowerShell이 Expo의 `expo-system-ui` 안내를 표준 오류에서
읽고 실패로 처리한 문제도 수정했다. 공통 native 명령 실행기는 실제 종료 코드로
성공 여부를 결정한다. Windows PowerShell에서 경고/출력/실패 코드 검사 3개와
실제 Expo prebuild가 통과했다.

기존 실기기 검증 버전의 Expo 58.0.21 / React Native 0.88.1 구성을 참고해
별도 작업 폴더에서 의존성 변경안을 준비했다. 캐시의 0.88.1 AAR는 게시된
모듈 메타데이터의 SHA-256과 일치했다. 사용자가 앱 빌드 중지를 확인한 뒤
Gradle 실행 작업이 없는 것도 확인하고 의존성 파일을 백업했다.
Expo 58.0.21, React Native 0.88.1 및 호환되는 asset/camera/font 패치를 적용했다.
설치된 17개 모듈은 Expo 패키지의 권장 버전 범위를 만족한다.
변경 후 모바일 단위 검사 5개, 모의 API를 사용하는 브라우저 흐름 검사 5개가
통과했고 브라우저 실행 오류는 없었다. 실제 Android APK 생성과 설치는 별도 검증한다.
공개 서버 창과 Docker는 유지한다.

## 위험도 3단계 표시 개선 (버전 8)

서버가 사용하는 위험도 코드와 기존 판정 규칙은 유지하고 앱 표시를 통일한다.

| API 코드 | 앱 표시 | 단계 | 색상 |
| --- | --- | --- | --- |
| OBSERVATION | 낮음 · 관찰 안내 | 1/3 | 초록 |
| WARNING | 주의 · 의료기관 확인 권장 | 2/3 | 주황 |
| EMERGENCY | 높음 · 긴급 확인 필요 | 3/3 | 빨강 |
| UNKNOWN 또는 인식하지 못한 값 | 판단 보류 | 단계 부여 안 함 | 회색 |

- 결과 화면에 큰 제목, 단계 수, 현재 단계 표시를 제공한다. 색상 외에도 문자로 구분한다.
- 홈 최근 분석과 기록 목록은 공통 표시를 사용한다. 문진 중/재시도 상태는 위험도와 구분한다.
- 문진 완료·재시도·새로고침 후 최신 응답을 목록에도 반영해 홈의 이전 상태가 남지 않도록 한다.
- 사진의 `normal_skin`/UNKNOWN 분류를 위험도 단계로 변환하지 않는다.
- 상처 유형이 불명확해도 문진 기반 응급 판정은 별도로 표시할 수 있도록 설명을 구분한다.
- 관리자 운영 API의 정보 노출 범위와 저장 데이터, AI 규칙, 가중치, 공개 서버 주소는 변경하지 않는다.
- 모바일 단위 검사 8개 및 모의 API 브라우저 검사 10개 통과. 3단계·UNKNOWN·미지원 값의
  결과/홈/기록 일치, 문진 완료 직후 홈 상태 갱신, 320px 화면 너비를 확인했다.
- 시뮬레이션 결과는 실제 환자 위험도 검증으로 기록하지 않는다.

Android/Expo 의존성 변경이 없는 이번 JS 수정은 빌드의 명시적 `-ReuseNativeProject` 옵션으로
기존 네이티브 프로젝트를 재사용한다. 기본 빌드 동작은 기존 전체 재생성을 유지한다.
버전 8 release 빌드와 APK 검사 19개가 통과했다. 기존 버전 7과 서명이 같으며
현재 공개 HTTPS 주소·카메라·전경 위치·로그인 복귀·비회원 API와 위험도 UI가 포함되어 있다.
설치 실행기의 `-VersionCode 8 -VerifyOnly`도 통과했다. 설치 로그와 사용자 응답으로
실제 휴대전화에 버전 8이 설치되고 위험도 단계 표시가 보인 것을 확인했다.

### 명칭 확정 및 레거시 처리 (버전 9)

버전 8 설치 로그와 사용자 확인으로 실제 휴대전화의 단계 표시를 확인했다.
이후 사용자가 확정한 다음 명칭을 버전 9에 반영했다. 위 버전 8의 초기 표시명은
현재 명세로 사용하지 않는다.

| 코드 | 확정 표시명 | 현재 3단계 포함 여부 |
| --- | --- | --- |
| OBSERVATION | 관찰 | 1/3 |
| WARNING | 경고 | 2/3 |
| EMERGENCY | 응급 | 3/3 |
| UNKNOWN | 판단 불가 | 별도 상태 |
| NORMAL | 정상 · 이전 결과 | 레거시 저장값만 표시, 단계 부여 안 함 |

기존 엔진의 판정 순서는 그대로 유지한다. 응급 규칙은 우선순위 순으로 검사해
첫 매칭에서 종료하며, 경고 규칙이 하나 이상 충족되면 경고를 반환한다.
관찰은 응급·경고에 해당하지 않고 필요한 문진·안전 항목이 채워진 경우의 기본값이다.
답변 unknown, 시나리오 unsure, 비전 게이트 실패 등은 기존 규칙에 따라 UNKNOWN을
반환한다. NORMAL을 관찰로 변경하거나 새로운 정상 판정을 생성하지 않는다.

모바일 단위 검사 9개와 모의 API 브라우저 검사 11개가 통과했다. 결과/홈/기록의
명칭 일치와 UNKNOWN/NORMAL의 단계 미부여, 좁은 화면 배치를 확인했다.
AI 규칙 파일과 엔진은 수정 전후 SHA-256이 일치한다. DB·API 계약·모델은 변경하지 않았다.
버전 9 Android release 빌드, APK 검사 20개, 설치 실행기의 서버/체크섬 확인이 통과했다.
실제 APK의 Hermes 번들에 확정한 한글 명칭과 이전 저장 결과 안내가 포함된 것도 확인했다.
