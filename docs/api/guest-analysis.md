# 비회원 분석 및 선택 동의 API

2026-11-05 로컬 구현. 기존 `/api/wc/analyses` 사진·문진·결과 계약은 유지한다.

## 비회원 접근

앱은 로그인 화면 대신 홈에서 시작한다. 사진 촬영·선택에는 계정이 필요하지 않다. 업로드 전에 비회원 서비스/개인정보 처리 및 건강정보 처리를 각각 확인한다. 학습용 이용은 별도 선택이며 기본값은 false이다.

| 요청 | 인증 | 동작 |
| --- | --- | --- |
| `GET /api/wc/auth/guest/policy` | 없음 | 버전과 공개 동의 문서 URL |
| `POST /api/wc/auth/guest` | 없음 | 명시적 필수 동의 후 비회원 접근 발급 |
| `POST /api/wc/auth/guest/resume` | 기기 키 | 같은 비회원의 접근 토큰 재발급 |
| `GET /api/wc/guest/consents` | GUEST | 현재 선택 동의와 이력 |
| `PUT /api/wc/guest/consents/training` | GUEST | 학습용 이용 선택·철회 |
| `DELETE /api/wc/guest` | GUEST | `{"confirmation":"삭제"}`로 해당 비회원 자료 삭제 |

시작 요청:

```json
{
  "deviceKey": "<암호학적 난수 32바이트의 소문자 64자리 hex>",
  "agreedService": true,
  "agreedHealthData": true,
  "policyVersion": "2026-11-04",
  "trainingGranted": false,
  "trainingVersion": "2026-11-04"
}
```

응답은 `token`, `userId`, `guest`, `trainingGranted`, `policyVersion`이다. 키는 네이티브 기기의 SecureStore에 먼저 보관하며 서버는 SHA-256 해시만 보관한다. 키 원문과 JWT는 로그·URL에 넣지 않는다. 웹 시연은 메모리만 사용하므로 새로고침 후 비회원 접근이 유지되지 않는다. 앱 삭제/기기 변경으로 키를 잃으면 자동 복구되지 않는다.

GUEST의 서버 API는 자신의 분석 생성·사진·문진·결과·경과 메모·삭제와 지역명 의료기관 검색을 허용한다. 회원 프로필, GPS 검색, 관리자 API는 거절한다. 비회원 기록은 소셜 계정에 자동 병합하지 않는다.

2026-11-06 모바일 버전 11부터 비회원 화면은 현재 실행 중인 분석의 문진·결과만 표시한다. 홈의 최근 분석, 과거 기록 목록, 경과 입력·비교는 회원에게만 표시하며 비회원은 목록 API를 호출하지 않는다. 새 분석을 시작하거나 앱 프로세스를 다시 시작하면 이전 결과를 화면에서 다시 열지 않는다. 소셜 로그인 후 로그아웃하면 기기 키로 비회원 접근을 복원하지만 과거 기록은 불러오지 않는다. 마이페이지의 선택 동의 변경·비회원 자료 전체 삭제 기능은 유지한다. 이 변경은 모바일 표시·요청 범위 변경이며, 서버 API 권한 폐지 또는 기존 데이터 삭제가 아니다. 이전 앱 버전의 API 계약은 유지한다.

생성 재시도는 동일 `clientRequestId`를 유지한다. 문진은 기존 `expectedVersion`, `questionId`, `clientRequestId` 계약을 사용한다. 계정 단위 생성 잠금과 소유자 조회를 재사용한다. 비회원 분석은 소유자별 최근 24시간 20건까지이며 동일 요청의 재시도는 먼저 처리한다. 시작 요청의 메모리 제한은 프로세스별/접속 주소별 1시간 30회다. 프록시 공유 주소 및 여러 서버에 대한 운영 수준의 제한은 별도 검토가 필요하다.

## 학습 이용

`analysis_sessions`에 `source_kind`, `training_eligible`, 동의 버전/시각, `training_review_status`를 추가했다. 기존 자료는 전부 제외 상태로 시작한다. 현재 버전에 동의한 이후의 새 사진만 `PENDING` 검수 대상으로 기록한다. 선택 동의만으로 자동 재학습·내보내기·라벨 확정은 하지 않는다. 기존 모델은 그대로다.

철회 시 해당 소유자의 기존 후보도 제외하고 `WITHDRAWN`으로 표시한다. 재동의는 과거 자료를 다시 포함하지 않는다. 실제 학습을 구현할 때에는 최신 동의와 삭제 상태, 원본 출처, 라벨, 중복 그룹 및 독립 평가 분할을 다시 확인해야 한다. `trainingExportEnabled`는 false이다.

관리 백업 복원은 과거 동의가 되살아나지 않도록 복원 대상의 학습 허용을 해제한다. 후보는 `RECONSENT_REQUIRED`로 바뀌고 이미지는 보존된다. 이후 재동의도 새 제출 자료에만 적용한다. 계정·기록 삭제 요청은 기존 삭제 이력과 복원 전 삭제 필터를 사용한다.

## GPS 선택 동의

기존 가입 완료 요청 `PUT /api/wc/users/me/consents`에 아래 선택 필드를 추가했다. 기존 클라이언트의 필드 생략도 허용한다. 필수 약관·개인정보·건강정보 동의 버전은 기존 `2026-11-03`을 유지한다.

```json
{"agreedLocation":false,"locationVersion":"2026-11-04"}
```

동의 변경은 `PUT /api/wc/users/me/consents/location`에 `{"granted":true,"version":"2026-11-04"}`를 보낸다. 현재 버전의 동의가 없는 `POST /api/wc/hospitals/public/nearby`는 403이다. 모바일 버전 12부터는 첫 가입에서 위치 동의를 선택하고 동의 저장을 마치면 OS 전경 위치 권한을 요청한다. 위치를 선택하지 않으면 요청하지 않으며, 권한 거절·요청 오류도 가입 완료를 막지 않는다. 실제 좌표 조회·서버 전송은 현재 위치 검색을 눌렀을 때만 이루어지고, 이때 권한도 다시 확인한다. 좌표는 기존 공공 API 검색 요청에만 사용하며 DB에 저장하지 않는다. 미동의/권한 거절 시 지역명 검색을 사용할 수 있다.

첫 가입의 ‘전체 동의’는 준비된 필수 항목과 선택 항목을 함께 선택하며, 개별 선택 해제 및 필수 항목만으로 가입도 가능하다. 기본 체크값은 모두 false다. 필수·위치 동의를 기존 가입 API에 저장한 다음, 학습 선택을 기존 `PUT /api/wc/users/me/consents/training`으로 저장한다. 두 호출은 하나의 DB 트랜잭션이 아니므로 두 번째 저장이 실패하면 완료 안내나 OS 권한 요청을 하지 않고 재시도 안내를 표시한다. 기존 가입 계정의 동의를 초기화하거나 자동 재동의시키지 않는다. 마이페이지에는 ‘개인정보 설정’ 진입 버튼을 두고 동의 변경·철회를 별도 화면에서 제공한다.
