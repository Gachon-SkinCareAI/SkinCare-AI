## 이번에 보완한 서비스

경과 사진 비교와 통증·메모 저장을 먼저 연결했다. 이어 관리자 분석 처리 현황과 AI 상태 조회를 추가했다. 의료적 판단 규칙과 기본 가중치는 변경하지 않았다. 앱의 연구·시연용 표시를 명시했다.

기획의 YOLOv8n과 로컬 실행 도구가 사용하는 det_v8s_wound 가중치 경로가 다르다. 단순 문서 이름을 맞추기 위해 모델을 교체하지 않는다. 추후 모델 검증 단계에서 실제 아키텍처와 버전을 확정해야 한다.

기존 데이터 공통 분할 산출물의 training_ready는 false다. 출처 미확인 자료의 검수와 누수 해소가 완료되었다고 표시하지 않는다. 기존 93.06% Macro F1은 독립 서비스 성능의 근거로 사용하지 않는다.

## 다음 구현 순서

1. 실제 MySQL 개발 환경과 재시작·복구 검증 완료. 기존 H2 기록을 이전하려면 별도 이전 범위 검토.
2. 소셜 로그인 구현·모의 왕복 검증 완료. 실제 제공자 키·약관 링크 연결, 제공자별 실제 인증 및 기기 검증.
3. 실제 공공 의료기관 자료와 위치 검색 연결.
4. 실기기 시나리오와 전체 서비스 회귀 시험.
5. 전문가 검수와 규칙·가이드 승인 절차. 이 단계 전까지 위험도·개별 케어는 연구·시연 범위 유지.

추가 조사에서 C:/Program Files/MySQL/MySQL Server 8.0의 MySQL 8.0.46을 찾았다. Docker 없이 이 실행 파일과 별도 데이터 디렉터리/13306 포트로 개발 DB를 구성했다. 기존 deploy/docker-compose.yml의 caremap용 PostgreSQL/Redis, 기존 MySQL 서비스와 H2 기록은 유지했다. deploy/mysql/README.md와 outputs/mysql-development-v1의 실행·검증 안내를 따른다.

일정과 담당자별 완료 날짜는 팀 합의가 없어 임의로 확정하지 않는다. 구현·로컬 검증·실환경 검증을 구분하며 0/6 또는 6/6 같은 단일 완료율로 합치지 않는다.

소셜 전용 전환 상세는 docs/social-auth.md를 따른다. 기본 모델/학습 데이터는 변경하지 않았다.
